# 胶片校色实施方案：档案文献、扫描参考与处理配方

日期：2026-11-12。状态：v2 契约与首个纵向切片已实现，见
[ADR-0009](adr/0009-film-color-grading-v2-and-filmarchive.md)；真实胶片模型与平台验收仍按证据门槛。

目标：摄影玩家选择胶片与输入类型后，在本机完成可撤销、可复现的校色；先让现有扫描成片
得到可用的正片校色流程，再逐步验证不同胶片的原始负片转正模型。胶片资料、实验参数与
已验证配置具有不同状态，不能因为选择了胶卷名称就自动改色。

## 1. 三种资料怎样结合

| 资源 | 在方案中的职责 | 不能直接推导的内容 |
|---|---|---|
| [朋友的 Film Archive](https://noeltong.github.io/filmarchive/) | 厂家原始文档与冲洗资料的补充入口，保留产品、分类与原始来源 | 文档分类不等于曲线可用性，也不等于已验证校色配置 |
| [本项目研究目录](film-color-catalog.md) | 扩展品牌、历史版本、玩家别称、来源证据与缺口，定位需要提取的技术图表 | 产品记录数不等于乳剂或校色方案数 |
| [用户扫描成片](film-color-reference-20261112.md) | 期望观感与真实场景对照：肤色、绿植、天空、日落、混合灯光、黑白影调 | 不提供同画面的原始曝光真值，不能充当片基/光源帧 |

工程判断：采用「文献约束 + 设备/同卷校准 + 可选观感调整」的组合。
厂表帮助理解胶片响应；实拍配对样本决定具体设备与处理参数是否有效。
HS1800扫描成片可以作为用户认可的观感目标，不能用不同场景的平均色或全图直方图定义
一条适用于所有胶卷的 HS1800 曲线。

## 2. 对朋友档案库的实际核验

本轮通过公开页面与静态资源读取，未使用登录或联系作者：

- [目录 JSON](https://noeltong.github.io/assets/filmarchive/catalog.json) 的 `schemaVersion=1`，
  `generatedAt=2026-10-27T17:18:49Z`；本轮快照包含110条文档记录，72条可见、38条隐藏，
  厂家标签为 Kodak、Fujifilm、Ilford、Foma、Adox、Rollei。
- `documents[]` 提供 `manufacturer/category/product/title/type/pages/sizeBytes/sourceUrl/path`，
  部分有 `hidden`。文档包含胶片、药水、相纸与冲洗规程；这些不是110个胶片配置。
- 目录的 `sourceUrl` 与本项目来源网址精确重合18条；网址不同的文件仍可能相同，
  不能将其余条目直接记作新增文献或新版本。
- 抽取 Ektar100、Gold200、T-Max P3200、Digibase CN200，公开PDF均可读取，页数与文件大小
  与目录一致。Ektar100、P3200的 SHA-256 与本机已有缓存相同；Gold200这份文件未匹配已有
  缓存指纹，仍需核对正文版本；Digibase CN200提供11页技术资料。
- `hidden` 是该站展示选择，不能变成我们删除来源或不核验文件的依据。`type` 也需复核：
  例如目录有标作 Technical Data 的发布稿、FAQ与订单清单，不能据标签直接提取胶片曲线。
- 目录没有逐条曲线点集、横纵轴单位、测量条件、误差或拟合结果。需另行提取和核验。

本机证据位于 `.local/film-color-reference-20261112/friend-archive/`：页面、目录、
PDF加载脚本、四份抽样文件及 `audit.json`。目录SHA-256为
`4554803b17e33d538f88a576184c730d25c1e7b2bb3eb6884578a9edbc67f664`。
本节数字仅为此次快照，不维护为站点永久统计；更新以目录和本机审计输出为准。

## 3. 用户实际使用的两条流程

### A. 已扫描成片校色——优先交付

适用于实验室已经转正的 TIFF/JPEG，包括用户现有图片。

1. 导入后默认保持普通边框模式。主动点击「校色」，选择「已转正扫描图」。
2. 显示源ICC、位深和原尺寸；缺ICC按项目既有规则标记假设，不冒充已有配置。
3. 可选胶卷身份、扫描设备和参考图。名称仅帮助检索；选择「炮塔160」不自动修改像素。
4. 并排看原图、参考图和当前结果。第一版提供曝光、RGB平衡、黑白点、曲线、饱和度，
   支持撤销、重置与选择性同卷同步。参考ROI先做统计与人工对照，不宣称任意画面自动配色。
5. 保存用户校色配方，冻结实际数值与版本。预览、单图、批量导出使用同一有效配方。

这一流程只使用正片调整，不去橙罩、不反相。已有扫描结果中的剪裁和量化损失不能靠输出
16-bit文件恢复；导出仍报告真实源事实与输出事实。

### B. 原始负片翻拍转正——独立验证

适用于真实RAW或来源明确的线性高位深负片数据。

1. 选择负片类型与实际工艺，先校准光源并取同卷未曝光片基。
2. 保留现有通用彩负作为可回退的算法版本；新胶片模型以明确的实验状态提供。
3. 用经过核验的曲线和设备标定生成基础正片，再叠加可选的观感调整。
4. 使用同画面的翻拍RAW与实验室扫描成片对照；客观色差另用已知灰卡/色卡检验。
5. 未通过对应胶片、设备和工艺验证前，不标为已验证配置，不扩散到所有同名胶片。

彩色反转不走彩负片基反相；黑白还需区分负片、正冲以及显影药水；电影卷区分实际工艺、
原始负片与打印/中间材料。以上分支分别验收，不因研究目录有型号就同时开放。

## 4. 第一批范围

| 顺序 | 对象 | 首轮目的 |
|---|---|---|
| 先做 | Gold200、Portra160/400、ProImage100、Fujicolor C200的人像与日景扫描 | 建立正片校色、参考对照与同卷配方保存，直接使用用户已有样片 |
| 再做 | Gold200、Portra160、C200真实负片配对实验 | 检验厂表与片基、光源、相机响应结合后的转正模型 |
| 独立扩展 | 5213/5219、HP5 Plus/PAN400、E100/Provia/Velvia | 分别处理电影工艺、黑白影调与反转，避免继承彩负假设 |
| 保留为资料 | 缺原表/缺版本/只有论坛身份线索的条目 | 可浏览和搜索，不提供伪造默认参数 |

这是实施次序建议；同名胶片的年代、规格和工艺分别记录，不把包装/销售名等同为独立乳剂。

## 5. 数据准备与配置生命周期

不把现有研究JSON直接当长期渲染DTO。先形成两类独立资料：

| 数据 | 最少必须保存的内容 |
|---|---|
| 文献记录 | 原作者/厂家、原始网址、镜像网址、文件SHA-256、正文版本/出版号、页码、读取状态、文档实际用途 |
| 曲线记录 | 对应胶片版本与工艺、图名、横纵轴含义/单位、测量标准、光源、原始采样点、有效区间、提取方法、复核与不确定度 |
| 实验配置 | 适用输入与处理域、所用文献/曲线指纹、设备/光源条件、算法版本、参数、实验样片、验收状态 |
| 用户观感配方 | 人工确认的曝光/曲线等数值、参考样片指纹、适用范围；与相机校准和片基分别保存 |

文献与胶片允许多对多关联：一份合订手册可覆盖多款胶片，一款胶片也可能有不同年代文档。
去重顺序为文件SHA-256、出版号/正文版本、胶片与工艺；名字和网址只做候选匹配。

生命周期建议：`indexed → document-verified → curve-reviewed → experimental → validated`。
缺字段、坐标不清、版本冲突等进入明确的问题状态；不得因文件名、页面存在或单张视觉满意自动晋级。
`validated` 必须绑定适用条件与验收证据，过期胶片或工艺变化不能继承无条件保证。

公开档案只作为研究和构建期资料来源；生产应用使用冻结的本地数值与来源索引，断网可运行。
本轮不复制对方站点代码、不将整站PDF打包。后续若分发文档或复用编目数据，分别记录作者、
厂家原文与编目数据的使用条件；这不阻塞现有链接核对、曲线研究和本机实验。

## 6. 算法路线与必须验证的问题

### 正片流程可以先明确实现

受控栅格读取及源ICC解释 → 统一浮点工作空间 → 正片调整 → 几何/装饰 → 输出色彩转换与编码。
使用既有 `FilmPositiveProcessor` 的确定顺序，参考图不进入源图的片基/光源校准字段。
零调整在同工作域保持恒等；普通模式与原有输出语义保持不变。

第一版保存人工调整配方；有严格配对帧后，才评估可复现的自动拟合。
不使用不同场景的全图直方图匹配来冒充设备校准，也不将白衣/天空自动当作已知中性色卡。

### 厂家曲线进入负片模型前需要技术探针

1. 数字化图表并逐条记录坐标和误差。曝光-logH/密度曲线与光谱曲线分别处理，不都当成
   一条归一化RGB曲线；原始曲线的有效曝光域不能被悄悄拉满到 `[0,1]`。
2. 测量/验证设备响应。厂家Status M或Status A密度不等于任意扫描RGB；相机通道包含
   光源、滤色响应及染料串扰，三条厂家特性曲线不能单独解决全色彩还原。
3. 比较「现有通用转换」「厂表约束的设备模型」「经过配对验证的经验模型」。
   必须在相同样片和输出条件下比较，以结果决定是否引入更复杂模型。
4. 当前 `FilmNegativeProcessor` 在已转换的线性工作RGB上做逐通道对数与密度归一化，
   是通用近似。不能把厂家密度曲线的反函数直接接在这里，声称就是物理还原。
   是否需要在相机/扫描原生通道域先建模，再进入正片工作空间，由探针确定；若需要，
   先扩展明确的数据阶段与兼容键，再实现新的算法版本。
5. 数据域不匹配、超出文献有效区间或模型未验证时，给出受控失败/实验状态；
   不靠静默夹断、缩图或放宽色差门槛获得通过。

HARMAN为Phoenix200/Azure提供的HS1800参数仍保留为特定胶片与扫描软件的调机建议，
不能直接把软件里的Chroma、CMY数值映射成应用的饱和度或RGB滑块。来源见
[研究目录中的官方扫描建议](film-color-catalog.md#官方扫描参数摘录)。

## 7. 与现有实现的接口边界

以下为待实现的契约方向，不是本轮已经生效的新API：

| 模块 | 当前事实 | 拟改动及边界 |
|---|---|---|
| Java引擎 | `ImageProcessingConfig`只接受sensor-raw/linear-tiff；`FilmProcessingPipeline`的正片阶段要求negative启用 | 先设计显式「编码栅格正片输入」并允许正片直通分支；不能把普通TIFF谎报为线性TIFF |
| Java引擎 | `ImageProcessingValidator`与`FilmNegativeProcessor`只接受generic-color-negative-v1 | 胶卷实验配置需新增版本及明确验证状态，未知/不兼容配置拒绝，保留v1请求行为 |
| Java引擎 | `FilmStageKeys`按实际参数/源与参考版本缓存 | 新增处理模式、配置内容指纹及算法版本进入正确阶段键；配方、分析、预览和导出签名一致 |
| 前端 | `FilmEditingPanel`现有控件写共享imageProcessing；RAW/TIFF输入有能力限制 | 新增输入选择、原图/参考/当前对照与配置状态；UI不得自行反相或另存一套校色参数 |
| Electron | 文件选择、受控路径与本地代理 | 复用白名单能力，不负责校色算法，不给渲染进程增加文件系统权限 |
| 摄影资产库 | 胶卷名称是摄影身份数据 | 继续与像素处理分开；选择胶卷名称不隐式开启处理 |

任何输入枚举、参考图语义或处理配置字段变更，先补ADR-0007及共享契约，再同步Java与前端。
预览/导出继续共用 `RenderRecipe.imageProcessing`。研究配置中的稳定ID、版本和内容指纹
用于追溯；冻结导出必须携带或解析并固定实际内容，不能只记录一个会漂移的目录名称。

首轮可在既有 `java-engine/src/main/resources/` 放单个版本化数据文件；代码继续进入现有
util/service/model等职责位置。不新增通用插件框架、云服务、第二套任务队列或浏览器图像引擎。
若后续为多款真实模型增加数据目录，理由是已经存在多个有版本的独立配置，不预先设计多层抽象。

## 9. 验证口径

- **结构与失败路径**：空body、缺必填、未知版本/ID、非法枚举、非有限数、非法尺寸/ROI、
  曲线点错误、ICC冲突、模式与片基/光源参数不兼容、参考文件变化都须覆盖。
- **数学与回归**：沿用ADR零调整与曝光的数值门槛；增加曲线插值、条件域、无反向/过冲、
  正片跳过反相、旧v1结果不变、缓存开关结果一致、配置变化使对应缓存失效。
- **实际输出**：同一冻结配方对比预览与全分辨率导出，几何与处理顺序一致；检查真实尺寸、
  位深、ICC与元数据，缺失/失败事实不记成零误差或通过。
- **视觉与色差**：用户认可的扫描图用来验收目标观感；已知色卡/中性梯尺用于独立色差与
  灰阶评价。配对帧需配准并排除片边、装饰、饱和反光。拟合前冻结训练/留出集、指标与门槛；
  不用对扫描成片的低色差宣称恢复了拍摄场景真值。
- **边界**：没有配对原始负片时，胶卷专属转正保持 `NOT_RUN`。没有高位深原数据时，
  不用8-bit扫描成片证明恢复了原始高光或色域。

实现时按 [CONTRIBUTING.md](../CONTRIBUTING.md) 跑所属模块检查：Java `mvn test`；
前端typecheck/test/build；Electron有改动才运行对应检查。此轮仅文档与只读审计，
检查引用、审计JSON及抽样PDF指纹，不运行应用测试、不打包。

## 10. 默认决策与待核验项

默认首版目标为用户可控的正片校色，目标观感可选；先保存人工配方，自动匹配另行实测。
全流程本地运行，来源资料不成为运行时网络依赖。

待核验项：同画面的原始负片配对、光源/色卡与设备条件；首批厂家曲线的具体测量域；
每款型号的正文版本适配；未来分发资料的使用条件。这些缺口已明确分配到任务，
当前可以直接开始FC01/FC02，像素入口变更先完成FC03契约设计。
