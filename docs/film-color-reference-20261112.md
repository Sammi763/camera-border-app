# 本机扫描成片校色参考（2026-11-12）

## 用途与归属

用户提供本机「胶片底片」图库，说明大多使用 Noritsu HS1800 扫描。本次读取文件元数据，
并查看按图像目录抽样的成片，用作底片数字化的视觉对照。归属是 **Java 引擎校色的参考资料与验收准备**；
本次没有修改算法、默认参数、前端或 Electron，也没有生成已验证的胶卷预设。

对应胶卷的厂家技术表、曲线用途和型号缺口见[胶片厂家技术资料与校色用途](film-manufacturer-color-sources.md)。

抽样中看到的是已经转正的扫描成片。它们可以定义期望观感，不能作为
`negative.filmBase` 的片基参考帧或 `negative.lightSource` 的光源参考帧，
也不能因为扩展名是 TIFF 就作为 `linear-tiff` 输入。

## 本机证据

原图保持原位，只读处理，不上传、不复制进 Git 或安装包。本机输出在仓库忽略目录
`.local/film-color-reference-20261112/`：

| 文件 | 内容 |
|---|---|
| `metadata.json` | 随包 ExifTool 读取的全库图像元数据快照 |
| `analysis.json` | 图像目录、抽样路径与 SHA-256、尺寸、ICC、显示缩略图统计和失败记录 |
| `roll-*.jpg` | 按图像目录分组的抽样联系表；编号不代表已经确认的物理胶卷编号 |
| `contact-*.jpg` | 分页汇总的联系表 |
| `analyze.py` | 本次本机抽样脚本，需要 Pillow 与 NumPy，仅开发分析使用 |

本次元数据快照包含 750 张 TIFF、60 张 JPEG，以及 9 个 FFF 文件。
TIFF/JPEG 分布在 30 个图像目录，按文件名字典序取约六分之一、中间和六分之五位置，
去重后抽看 88 张；抽样不等于逐张质检。FFF 仅做元数据盘点，没有解码或纳入视觉结论；
THM 不作为独立校色样片。

TIFF 中 724 张为每通道 8-bit，26 张为每通道 16-bit。TIFF/JPEG 中，
26 张带 Adobe RGB (1998) ICC，75 张带 sRGB ICC，其余未读到嵌入 ICC。
位深和扩展名均不能证明线性传递函数。

部分元数据包含 `NORITSU KOKI`、`EZ Controller` 或 `QSS-32_33`，也包含 Photoshop、
Capture One 记录。它们不足以逐张证明使用了 HS1800，亦不能分离扫描软件、人工调色与
胶卷自身的贡献。来源记录保留为「用户说明大多为 HS1800」，不能升级成统一设备事实。

## 色彩参考分组

以下是联系表中的视觉观察与使用方向，**不是对胶卷固有色彩的测量**。
胶卷名称来自目录，型号、冲洗方式与扫描设置仍需单独确认。

| 参考组 | 抽样观察 | 校色时优先对照 |
|---|---|---|
| FF Lab 炮塔160、金200人像；柯达人像100；富士c400人像 | 肤色整体较克制；同场白衣、深色衣物和红色领巾提供多个对照物；不同组冷暖有差别 | 面部明暗与肤色、白衣是否明显偏色、红色细节是否丢失；衣物不能当作已知反射率的色卡 |
| 柯达金200日景与日落 | 日景绿植与浅色建筑可对照层次；日落组明显受暖光影响 | 日景与日落分开，保留光照气氛，避免用日落平均色决定全局白平衡 |
| 富士c200/c400日景 | 有丰富绿植、天空、水面和建筑；部分场景反差较强 | 绿植层次、青蓝色与高光，避免只提高饱和度导致绿色成片合并 |
| 乐凯日景 | 各组差异较大；部分抽样有明显黄绿/粉色倾向、低反差或条纹候选 | 分卷检查；有异常纹理、偏色或曝光问题的图先复核原图，再决定是否纳入风格参考 |
| 5213日景、5219/炮塔400夜景与室内 | 人工光源与日光混合，暖灯和青色暗部并存；同名场景有 TIFF/JPEG 版本 | 按光源分组，保护肤色与灯光颜色；重复场景不应增加拟合或验收权重 |
| HP5 Plus、PAN400黑白 | 抽样覆盖低反差与高反差结果，部分浅灰成片有明显纹理候选 | 单独检查影调、暗部与亮部层次，不参与彩色样片的通道平衡或饱和度目标统计 |

首轮视觉对照优先使用：人像组检查肤色与中性色；金200与富士日景组检查自然色与层次；
夜景组检查混合光；黑白组检查曲线。乐凯明显偏色或有纹理疑问的抽样先作为异常案例。
同一场景的跨胶卷照片可以辅助比较观感，但没有相同曝光、光照与扫描设置时，不能视为严格配对。

## 在现有校色管线中怎么用

1. 参考图按其嵌入 ICC 转成统一显示空间后再比较。没有 ICC 时，联系表仅以
   sRGB 假设显示；这个假设不表示源图已经证明是 sRGB，也不能据此覆盖原图配置。
   联系表统计来自缩略图的 8-bit 显示 RGB；不是原片线性测量，不能反推出 RAW 通道增益或剪裁事实。
2. 底片翻拍仍先按自己的光源与同卷片基完成基础转正，不能拿扫描成片取代这一步。
   已转正的扫描 TIFF/JPEG 加边框时继续走普通模式，保持默认色彩行为。
3. 与参考图在相同显示条件下对照，先调整曝光与 RGB 平衡，再看黑白点、总曲线、
   分通道曲线与饱和度。参数使用现有 `RenderRecipe.imageProcessing.positive`，
   不新增预览专用字段，也不根据胶卷名称自动套用参数。
4. 需要建立可复用的数值校色时，补充**同一画面**的原始负片翻拍 RAW 与对应扫描成片，
   记录物理胶卷、片基、光源、方向、裁切、源配置与内容指纹；先配准画面，再选择有效区域。
   若需要客观色差验收，还需同条件的灰卡/色卡及测量目标。
5. 用一部分配对帧调整参数，另一部分未参与调整的帧检查泛化；按人像、日景、夜景分组，
   保存配方、前后预览与导出回读结果。不能将不同场景的全图直方图直接匹配为
   「HS1800 曲线」，也不能直接把显示 RGB 的曲线数值套到线性 Rec.2020 工作图。

本次完成的是参考资料盘点与视觉分组。真实负片转正、Gold/Portra 专属还原、
数值色差及预览/导出一致性仍按 [样片矩阵](test-samples.md#8-底片数字化样片t00-盘点未验收)
和 [ADR-0007](adr/0007-explicit-film-digitization-mode.md) 的验收要求执行；不能把本次抽样查看记成算法验收通过。
