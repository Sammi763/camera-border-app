# 摄影边框工具实施任务清单

> 本文把 [PRD](prd.md) 的产品要求拆成可执行任务。任务按依赖排序，默认全部属于待实现或待验收状态；代码已有的旧 Roll、扫描仪、实验室和冲洗结构不代表它们是当前产品需求。
>
> 交付目标：用户在 Windows 和 macOS 上安装 `.exe` / `.dmg` 后，无需登录、无需安装 Java，即可完成图片导入、数码 EXIF 读取或胶片摄影预设补充、模板排版、预览和批量导出。图片默认不离开本机。

## 0. 统一约定

### 0.1 产品对象边界

- 图片队列：用户当前要处理的图片集合。
- 摄影资产：可复用的相机、镜头、胶片。
- 摄影预设：可分类的拍摄身份组合，服务于“补充或覆盖图片信息”。
- 视觉模板：边框、文字、渐变、Logo 和导出样式，服务于“如何排版”。
- `RenderRecipe`：预览与导出的唯一渲染配方。

当前版本不新增或扩展以下对象：Roll、冲洗工艺、扫描仪、实验室、暗房流程、登录账号。

### 0.2 字段来源优先级

```text
每图覆盖 > 摄影预设 > EXIF > 空
```

这条优先级必须同时适用于 Canvas 预览、Java 引擎预览、单图导出和批量导出。缺失字段替换为空，不显示 `undefined`、`null` 或多余分隔符。

### 0.3 完成要求

每个实现任务都需要：

- 成功路径测试；
- 空值、缺字段、非法枚举、非法尺寸或无效引用等失败路径测试；
- 更新对应模块 README 或 [cookbook](cookbook.md)；
- 通过所属模块的 typecheck/test；
- 涉及渲染的改动必须验证四条预览/导出链路一致。

## 1. P0：可安装的摄影师 MVP

### P0-01 固化产品契约与迁移边界

- 归属：产品文档 + frontend/java-engine/electron 协同。
- 依赖：无。
- 工作内容：以 `captureFormat` 替代产品层 `filmFormat`，以 `ShootingPreset` 替代产品层 `Roll`；确认旧字段的兼容读取、迁移提示和停止扩展策略。
- 完成条件：PRD、README、cookbook、数据模型、变量清单不再把 Roll 当作 MVP 主流程；迁移策略写入 ADR 或模块文档。
- 验证：全仓库检索旧术语，确认只出现在迁移说明或延期说明中。

### P0-02 建立统一拍摄画幅模型

- 归属：java-engine + frontend。
- 依赖：P0-01。
- 工作内容：定义画幅 ID、显示名、归类、比例、推荐边框和是否可裁剪建议。
- 必须覆盖：
  - 数码：M43、APS-C、135 全画幅、4433 中画幅；
  - 胶片：半格、135、645、6x6、6x7、6x8、6x9、6x10、6x12；6x12 保留，6x10 作为新增画幅。
- 完成条件：画幅可以用于信息展示和边框推荐；切换画幅不会静默裁剪、改尺寸或覆盖用户手动设置。
- 失败路径：未知画幅 ID、非法比例、负数边框、空名称返回可理解的 4xx 或前端校验错误。
- 验证：Java Controller/Service 测试 + 前端类型和交互测试。

### P0-03 统一 EXIF 读取与标准化

- 归属：java-engine + frontend metadata。
- 依赖：P0-01。
- 工作内容：从 EXIF 读取 Make/Model、镜头、焦距、光圈、快门、ISO、拍摄时间、方向等字段，统一为前端 `PhotoIdentity`/metadata 可消费的结构。
- 完成条件：数码图片无需创建摄影预设就能展示基础摄影信息；字段缺失时正常降级为空；原始 EXIF JSON 可用于调试但不直接作为模板契约。
- 失败路径：无 EXIF、损坏图片、未知字段类型、非法曝光值、路径不存在。
- 验证：样片覆盖完整 EXIF、部分 EXIF、无 EXIF 和损坏输入；运行 `cd java-engine && mvn test` 与前端测试。

### P0-04 收敛摄影资产库

- 归属：frontend metadata + electron preload/IPC。
- 依赖：P0-01。
- 工作内容：资产库只实现相机、镜头、胶片三类；支持新增、编辑、复制、删除、搜索和引用。
- 资产字段：
  - 相机：品牌、型号、别名、备注；
  - 镜头：品牌、型号、焦段、最大光圈、卡口、备注；
  - 胶片：品牌、名称、ISO、类型、色彩倾向、停产状态、备注。
- 完成条件：Electron 模式持久化到 `userData`；浏览器模式降级到 `localStorage`；资产引用不存在时显示原始文本或空值，不导致工作台崩溃。
- 失败路径：空名称、重复 ID、非法类型、删除被引用资产、损坏的本地 JSON。
- 验证：资产 codec/hook/component 测试；重启后读取验证；确认 preload 只暴露白名单 API。

### P0-05 实现可分类摄影预设

- 归属：frontend metadata + electron preload/IPC。
- 依赖：P0-02、P0-04。
- 工作内容：创建 `ShootingPreset`，支持名称、分类、拍摄画幅、相机/镜头/胶片资产引用、默认地点和备注；支持创建、编辑、复制、删除、分类筛选和应用范围选择。
- 应用范围：当前图片、选中图片、全部图片。
- 完成条件：胶片图片可通过一个预设批量补齐拍摄身份；数码图片可选择预设修正或补充 EXIF；预设、模板和图片队列相互独立。
- 失败路径：空名称、缺失画幅、无效资产 ID、重复分类、删除后仍有图片引用。
- 验证：每图覆盖 > 摄影预设 > EXIF > 空的优先级测试；Electron 与 localStorage 两种持久化路径测试。

### P0-06 统一有效摄影信息与变量解析

- 归属：frontend metadata + java-engine metadata/render。
- 依赖：P0-03、P0-05。
- 工作内容：实现 `PhotoIdentity` 合并函数，删除产品层对 Developer/Scanner/Lab/RollName 的依赖；新增 `CaptureFormat` 变量，保留相机、镜头、胶片、曝光、时间、地点、帧号和自定义文本。
- 完成条件：变量缺失时清理多余分隔符；同一个模板在 Canvas、引擎预览、单图导出、批量导出显示相同内容。
- 失败路径：非法变量、循环引用、空字符串、类型错误、旧 Roll 字段输入。
- 验证：更新 `resolveTextVariables` 和 Java metadata formatter 测试，并执行四链路冒烟。

### P0-07 明确视觉模板与摄影预设的职责

- 归属：frontend template + settings。
- 依赖：P0-01、P0-06。
- 工作内容：视觉模板只保存边框、背景、文字、渐变、Logo 和导出设置；摄影预设只保存拍摄身份；模板分类使用经典、胶片信息、极简、分享等视觉语义。
- 完成条件：应用视觉模板不会覆盖摄影预设；应用摄影预设不会改变边框和文字布局；模板 JSON 使用 `captureFormat` 或通过 `PhotoIdentity` 获取画幅，不再新增 `roll`。
- 失败路径：旧模板字段、未知分类、非法边框尺寸、缺失模板字段。
- 验证：模板 codec、内置模板校验、导入导出兼容测试。

### P0-08 收敛导入、队列和批量导出闭环

- 归属：frontend + electron + java-engine。
- 依赖：P0-06、P0-07。
- 工作内容：完善拖拽/多选导入、图片切换、删除、单图导出、批量导出、失败重试、文件名冲突和导出后打开目录。
- 完成条件：用户可明确看到当前图片、选中图片、全部图片的作用范围；失败项不影响其他图片；原图不被覆盖；输出尺寸和质量变化有明确提示。
- 失败路径：空队列、不可读文件、输出目录无权限、文件名冲突、引擎离线、部分任务失败。
- 验证：前端 integration/E2E + Java API 失败路径测试；确认导出状态不会因轮询/超时误判。

### P0-09 保证预览与导出同源

- 归属：frontend + java-engine。
- 依赖：P0-06、P0-07、P0-08。
- 工作内容：检查 Canvas 即时预览、引擎预览、单图导出、批量导出是否都由同一套 `RenderRecipe` 驱动；隐藏或实现所有会造成“预览有、导出无”的控件。
- 完成条件：文字、边框、渐变、画幅推荐、摄影信息在四条链路一致；预览失败时降级行为可解释。
- 失败路径：空 recipe、缺 imagePath、非法颜色、非法尺寸、Java 引擎返回 4xx/5xx。
- 验证：执行 cookbook 的一致性检查；补充固定样片回归。

### P0-10 完成 Windows/macOS 打包交付

- 归属：electron + 发布工程。
- 依赖：P0-08、P0-09。
- 工作内容：配置 electron-builder；打包 Java Engine 与随包 Java Runtime；处理 `resourcesPath`、临时端口、进程生命周期、日志、启动失败和退出清理；产出 Windows `.exe` 与 macOS `.dmg`。
- 完成条件：干净机器安装后直接运行，不要求用户安装 Java、不要求登录；图片和用户资产仍在本机；Windows/macOS 安装、启动、导入、导出和卸载路径可验证。
- 失败路径：端口占用、Java Engine 启动失败、资源路径含空格、无写权限、macOS 未签名提示、Windows Defender/NSIS 安装失败。
- 验证：至少一台 Windows 和一台 macOS 实机或干净虚拟机手工验收；CI 负责构建检查，签名和公证另行处理。

### P0-11 MVP 回归与发布门禁

- 归属：全模块。
- 依赖：P0-02 至 P0-10。
- 工作内容：准备数字 EXIF、胶片无 EXIF、横竖图、6x10/6x12 等不同画幅、无元数据、损坏图片和大图样片；记录安装包版本、引擎版本和导出结果。
- 完成条件：README、PRD、cookbook、tasks 与实际行为一致；无旧 Roll 主流程文案，只保留迁移/延期说明；核心流程离线可用。
- 验证命令：

```bash
pnpm --filter frontend typecheck
pnpm --filter frontend test
pnpm --filter electron typecheck
cd java-engine && mvn test
```

## 2. P1：效率与排版增强

### P1-01 多段文字和信息布局

- 归属：frontend settings/template + java-engine renderer。
- 依赖：P0-06、P0-09。
- 完成条件：支持多段文字、左中右三栏、行距/字距、阴影/描边/背景条，并在四条渲染链路一致。

### P1-02 批量作用域与会话恢复

- 归属：frontend queue/state + electron persistence。
- 依赖：P0-05、P0-08。
- 完成条件：当前/选中/全部图片的操作范围可见；支持撤销/重做、最近模板、异常退出后的会话恢复。

### P1-03 Logo、模板卡片和社交尺寸

- 归属：frontend template/settings + java-engine export。
- 依赖：P0-07、P0-08。
- 完成条件：Logo 识别可关闭且有文本回退；模板卡片能快速预览；社交尺寸不放大原图并明确输出尺寸。

### P1-04 预览交互

- 归属：frontend preview。
- 依赖：P0-09。
- 完成条件：缩放、拖拽、适应屏幕、网格辅助和裁剪拖动不会改变未确认的导出设置。

## 3. P2：专业高保真

### P2-01 TIFF、ICC、16-bit 与元数据

- 归属：java-engine + export UI。
- 依赖：P0-11。
- 完成条件：对 TIFF、ICC、16-bit、EXIF/XMP/IPTC/GPS 的支持范围明确展示，不支持的字段给出保真报告。

### P2-02 样片回归与导出保真报告

- 归属：java-engine tests + docs。
- 依赖：P2-01。
- 完成条件：报告说明尺寸、格式、位深、色彩空间、元数据的保留/变化原因；无色彩效果时有稳定的色彩一致性基线。

## 4. P3：明确延期的可选能力

以下项目不进入当前 MVP，也不应成为 P0 的隐性依赖：

- Contact Sheet 接触表；
- 暗房、档案馆、Negative Sleeve 等语境模板；
- 胶片色彩效果、颗粒和创意滤镜；
- Roll、冲洗、扫描、实验室管理；
- 登录、云同步、在线模板市场；
- AI 模板推荐、配色、文案和导出检查。

如果未来重新启动这些方向，必须先补充独立 PRD、数据模型、隐私边界和迁移方案，不能把字段直接塞回当前 `ShootingPreset`。

## 5. 任务执行顺序

```text
P0-01
  ├─ P0-02 ─┐
  ├─ P0-03 ─┼─ P0-06 ─┐
  └─ P0-04 ─┘         ├─ P0-07 ─ P0-08 ─ P0-09 ─ P0-10 ─ P0-11
          └─ P0-05 ───┘
                                      └─ P1/P2
```

并行建议：P0-02、P0-03、P0-04 可并行；P0-05 依赖画幅和资产库；P0-06 依赖 EXIF 与预设；打包任务等核心闭环稳定后进入，但应尽早建立最小打包验证，避免最后才发现 Java Runtime 或资源路径问题。
