# 图片边框工具项目文档（PRD 与路线图）

> 本文档整合原 PRD、当前项目实现状态，以及对 Copicseal、远山、Polaroid Style Generator、PhotoBorderMasker、OneFrame 等同类项目的功能分析。目标是把本项目收敛为一款面向摄影用户的本地桌面图片边框工具，并明确后续功能优先级。
>
> **文档角色**：本文件是产品 PRD 与路线图，回答「做什么、为什么做、分阶段怎么做」。本文件 §0 冻结最终产品契约；§4 记录当前实现状态。README 只做面向用户的摘要，不能覆盖 §0；架构约束与边界见 [ARCHITECTURE.md](../ARCHITECTURE.md)；开发环境、命令与验证路径见 [CONTRIBUTING.md](../CONTRIBUTING.md)；关键取舍的原因见 [docs/adr/](adr/)。

## 0. 阶段 0：产品契约与验收基线（冻结）

本节是最终产品支持范围、术语、导出档位和样片验收的唯一权威。README、发布清单和
操作手册只引用或解释本节，不得自行增加格式、平台、导出档位或产品能力。工程状态和
最终支持范围必须分开记录：

- **当前已实现**：当前 HEAD 中已经存在的代码或可验证流程；不等于最终产品已经支持。
- **本计划目标**：本节冻结的最终目标；在样片矩阵和平台验收完成前，不得写成“当前支持”。
- **未验收**：代码存在但未完成目标平台、格式、位深、ICC 或元数据验证时，只能标记为未验收。

### 0.1 最终平台

最终发行平台只有以下三种：

| 平台 | 架构 | 交付形态 | 口径 |
|---|---|---|---|
| macOS | arm64 | `.dmg` | 最终支持 |
| macOS | x64 | `.dmg` | 最终支持 |
| Windows | x64 | `.exe`（NSIS） | 最终支持 |

Linux、Windows arm64 和移动端不属于最终发行范围。跨平台交叉构建只能证明资源或配置
正确，不能替代对应平台的安装、启动和照片流程验收。

### 0.2 输入格式

最终产品支持 JPEG、PNG、TIFF、HEIC/HEIF，以及带有可读取内嵌 JPEG 预览的 RAW 文件。
其中 JPEG/JPG、TIFF/TIF 的大小写扩展名等价。WebP、BMP 等其他格式即使开发环境的
系统解码器偶尔可以读取，也不属于最终支持格式。

本阶段 RAW 的扩展名验收集合冻结为 NEF、CR2、CR3、ARW、RAF、DNG、ORF、RW2、PEF；每个
扩展名都必须有“带内嵌 JPEG”和“无内嵌 JPEG”两份真实相机样片。未列出的 RAW 扩展名不
属于最终支持范围，除非先更新本节和样片矩阵。

RAW 的产品语义固定为“读取内嵌 JPEG 预览”：不做传感器数据解码、去马赛克、曝光/白平衡
调整或其他真实显影。如果 RAW 没有可读取的内嵌 JPEG，导入、预览或导出必须明确失败并
说明原因，不得用其他缩略图冒充真实 RAW 显影，也不得宣称支持真实 RAW 显影。

### 0.3 输出格式与位深

最终产品输出格式固定为：

| 格式 | 支持位深 | 说明 |
|---|---|---|
| JPEG | 8-bit | 有损输出；质量由导出档位固定 |
| PNG | 8-bit、16-bit | 无损输出；位深必须在结果中明确 |
| TIFF | 8-bit、16-bit | 用于高保真输出；位深按导出档位和源图确定 |

换句话说，最终输出格式就是 JPEG 8-bit、PNG 8/16-bit、TIFF 8/16-bit；其中 PNG/TIFF
的 8/16-bit 是格式级位深能力，不代表新增导出档位。

三个固定导出档位只允许使用下表定义的参数。下表的格式是每档的规范默认格式；PNG 是
必须提供的同档位输出格式变体，不是第四个导出档位。导出界面必须分别显示“导出档位”和
“输出格式”，并且只允许下表中的组合；选择 PNG 不得改变所选档位的尺寸、色彩或元数据
策略，PNG 的输出位深也必须明确展示。

| 导出档位 | 格式与参数 | 尺寸 | 色彩 | 元数据 |
|---|---|---|---|---|
| **快速分享** | JPEG 8-bit，质量 92 | 长边 2048；源图更小则不放大 | 转为 sRGB | 移除 GPS/位置；非位置元数据按源格式可表达范围保留，实际差异必须可见 |
| **标准交付** | JPEG 8-bit，质量 95 | 原图尺寸 | 保留源 ICC | 保留源 ICC 和全部元数据，包含 GPS/位置 |
| **高保真归档** | TIFF，源位深（8/16-bit） | 原图尺寸 | 保留源 ICC | 保留源 ICC 和全部元数据，包含 GPS/位置 |

| 导出档位 | 规范默认格式 | 必须提供的 PNG 变体 | PNG 变体位深 |
|---|---|---|---|
| 快速分享 | JPEG 8-bit（质量 92） | PNG | 8-bit |
| 标准交付 | JPEG 8-bit（质量 95） | PNG | 8-bit |
| 高保真归档 | TIFF | PNG | 源位深（8/16-bit） |

PNG 变体沿用所选档位的尺寸、色彩和 GPS/位置策略；JPEG 质量参数只对 JPEG 规范默认
格式生效。目标容器无法承载的源元数据不得静默丢弃，必须明确标记不支持或使导出失败。

“全部元数据”至少包括可读取的 EXIF、XMP、IPTC 和 GPS/位置字段，以及目标容器能够
承载的其他源元数据。源图没有 ICC 或某类元数据时不凭空创建；结果必须明确标注“源无此项”。
源位深不是 8-bit 或 16-bit 时，不能静默伪装成“源位深保留”，必须在导出前给出明确的
降级或不支持结果。

快速分享必须移除 GPS/位置；标准交付和高保真归档必须保留 GPS/位置。三档都不得覆盖
原图，导出结果必须写入用户明确选择的新路径。

### 0.4 统一术语

产品文案、验收清单和新增文档统一使用以下术语。代码中的历史类型名（例如
`ShootingPreset`）可以保留，但说明文字必须使用对应的中文产品术语。

| 统一术语 | 定义 | 不应混用的说法 |
|---|---|---|
| **版式** | 边框、文字、拍摄信息及其位置/间距/层级的组合；用户选择的是版式 | 视觉模板、样式模板（除竞品原名或历史代码说明外） |
| **拍摄信息预设** | 可复用的相机、镜头、胶片、拍摄画幅及可选地点等拍摄身份信息 | 摄影预设、设备预设 |
| **拍摄画幅** | 照片实际拍摄格式或比例的描述，如 135、6×6、APS-C | 把它当作裁剪比例或导出尺寸 |
| **边框布局建议** | 根据拍摄画幅提供的边框尺寸/留白建议 | 自动裁剪、强制改尺寸 |

拍摄画幅只提供边框布局建议，不自动裁剪、不改变原图比例、不改变导出尺寸。版式只
负责排版；拍摄信息预设只负责拍摄身份，两者互不写回原图元数据。

### 0.5 明确不做

最终产品不做修图（包括曝光、白平衡、曲线、局部调整等）、云同步、登录、自动更新和
真实 RAW 显影。产品也不因为导入 RAW、HEIC/HEIF 或使用高保真档位而把图片上传到云端。

### 0.6 验收入口

格式、位深、ICC 和元数据的样片矩阵见 [`docs/test-samples.md`](test-samples.md)。每个
最终平台都必须完成安装/启动/离线导入/预览/三档导出回归；任何一项未完成，只能称为
“当前已实现”或“未验收”，不能称为“最终支持”。

## 1. 产品定位

### 1.1 产品一句话

面向数码与胶片摄影用户的本地桌面图片边框工具，支持读取数码 EXIF、用拍摄信息预设
补充拍摄信息、添加高质量边框与版式，并批量导出成品。应用最终只以 macOS arm64、
macOS x64 的 `.dmg` 和 Windows x64 的 `.exe` 交付，不要求登录。

### 1.2 目标用户

- 数码摄影用户
- 胶片摄影用户
- 摄影博主和内容创作者
- 需要批量出图的摄影工作室
- 对 TIFF、ICC、EXIF、16-bit 有要求的进阶摄影用户

### 1.3 核心价值

- 快速生成适合社交平台和作品展示的照片边框。
- 数码照片自动读取并排版相机、镜头、光圈、快门、ISO、焦距等 EXIF 信息。
- 胶片照片通过可分类的拍摄信息预设补充相机、镜头、胶片和拍摄画幅等信息。
- 支持版式复用和批量导出，减少重复劳动。
- 在专业模式下尽量保留原图分辨率、色彩空间、位深和元数据。

### 1.4 产品边界

最终产品不做修图、登录、云同步、自动更新、真实 RAW 显影、移动端和在线版式商店。
也不做 Roll、冲洗、扫描、实验室或暗房工作流。项目重点是“边框、文字、拍摄信息、
版式、批量、高质量导出”，并保证在 macOS arm64、macOS x64 和 Windows x64 上可安装运行。

## 2. 竞品与参考项目分析

### 2.1 Copicseal

项目地址：https://github.com/copicseal/copicseal

定位：模板化相框和水印生成器。

优点：

- 已经是完整 Electron 桌面应用，具备打包、发布、自动更新配置。
- 模板表达力强，模板本质是 Vue/CSS 组件，可以做白边、圆角、PS 启动窗、时间戳、内嵌文字、重复水印等复杂版式。
- EXIF 变量系统成熟，可用 `{FocalLength}`、`{FNumber}`、`{ExposureTime}`、`{ISOSpeedRatings}` 等变量拼接文字。
- 支持系统字体读取、全局字体选择、输出尺寸预设、批量导出、导出进度。
- 支持相机/镜头拍摄信息预设，可快速覆盖当前图片参数。
- 使用 exiftool 写回部分元数据，说明元数据保留是用户真实需要。

可吸收设计：

- 文本变量插入器。
- 系统字体读取与字体收藏。
- 输出尺寸预设。
- 拍摄信息预设库。
- 版式卡片和版式参数自动生成面板。
- 发布打包链路（不吸收自动更新）。

不建议照搬：

- 它的最终导出依赖 DOM/Puppeteer 截图，适合模板表达，但不适合本项目长期追求 TIFF、16-bit、ICC 的高保真路线。

### 2.2 远山 yuanshan

项目地址：https://github.com/lozyHao/yuanshan

定位：照片边框、水印、参数展示和配置分享工具。

优点：

- 支持自定义边框、背景、图片、文字、水印样式。
- 参数修改后自动实时预览，强调防抖刷新。
- 内置 6 套常用风格版式，如经典模糊、纯白边框、极简黑框、宽边留白、圆角阴影、底部信息条。
- 支持配置导入/导出，把基础配置、文字模板、相机参数整合成 JSON，方便迁移和分享。
- 支持相机自带参数编辑、新增和手动修正。
- 支持预览图拖拽/缩放，方便查看细节。
- 有字体转图片、画板等辅助工具，说明“签名/花字/手写感”有用户价值。
- Canvas 绘制中包含圆角、投影、模糊背景、水印位置、文字背景、主边框/副边框等细节。

可吸收设计：

- 版式首屏卡片化。
- 配置导入/导出 JSON。
- 背景模糊和毛玻璃风格。
- 圆角、投影、文字背景、水印图层。
- 预览缩放/拖拽。
- 字体签名转图片或手写签名素材。

### 2.3 Polaroid Style Generator

项目地址：https://github.com/Sacilave/polaroid-style-generator

定位：拍立得框架和复古胶片效果生成器。

优点：

- 框架和色彩效果分离，架构简单清晰。
- 支持 original、polaroid、symmetric 三种框架。
- 拍立得边框比例明确：左右和顶部按宽度比例计算，底部加宽。
- 支持复古、黑白胶片、即时显影、交叉冲洗、电影胶片、复古彩色等多组色彩效果。
- 支持随机组合、一键生成所有组合。
- 使用颗粒感、饱和度、对比度、色温等简单参数实现胶片氛围。

可吸收设计：

- 拍立得版式作为首批版式之一。
- 胶片色彩预设作为可选效果，但默认不改变原图。
- “框架预设”和“色彩预设”分离，避免模板系统混乱。
- 随机预览/随机组合可作为后续创意功能。

注意：

- 它会改变照片色彩，本项目应把这类能力放到“创意模式”，不能影响高保真导出默认值。

### 2.4 PhotoBorderMasker

项目地址：https://github.com/WekyJay/PhotoBorderMasker

定位：基于 Konva 的图片边框和 EXIF 信息可视化编辑器。

优点：

- 使用 Konva 提供可拖拽、可选中、可复制、可删除的图层编辑体验。
- 支持网格、适应屏幕、右键菜单、元素选择提示。
- 边框模型包含 thickness、top、right、bottom、left、innerPadding、outerPadding、color、radius、style。
- 支持自定义文字元素、矩形元素、品牌 Logo、EXIF 参数文本。
- 模板支持保存、复制、删除、导入、导出 JSON。
- 支持拖拽 JSON 模板文件直接应用。
- EXIF 字段可拖拽到画布或文本中。

可吸收设计：

- 进阶模板编辑器可以采用“图层/元素”模型。
- 模板 JSON 应包含 border、items、text、logo、metadata 这些结构化数据。
- EXIF 字段拖拽插入文本，是很适合摄影用户的交互。
- 右键菜单和网格辅助能明显提升编辑效率。

阶段建议：

- MVP 不需要完整 Konva 编辑器。
- V2 可加入“高级模板编辑器”，允许自由拖放文字、Logo、矩形和装饰元素。

### 2.5 OneFrame

项目地址：https://github.com/IceyVanci/OneFrame

定位：多样式摄影信息边框桌面工具。

优点：

- 首页以 Type A-H 样式卡片展示，用户先选风格再导入图片，路径很清晰。
- 样式覆盖白色下边框、黑色下边框、横向布局、Logo 居中布局、1:1 裁剪、画中画、居中参数、全画幅叠加文字。
- 自动识别相机厂商并显示 Logo。
- 支持 Logo 显示开关、参数显示开关、拍摄时间显示开关、自定义署名。
- 部分样式支持拖动裁剪。
- 导出时保留 JPG EXIF，使用预览模块和导出模块双轨，强调预览与导出一致。
- 有较完整的样式注册表，预览、导出、编辑面板按样式拆分。

可吸收设计：

- 首页提供“样式选择”入口，而不是只给参数面板。
- 内置 6-8 个首批模板，按视觉用途命名。
- 相机品牌 Logo 自动识别和深浅背景自动适配。
- 每个模板可以有自己的参数面板。
- 预览模块和导出模块共享布局计算，避免看起来对、导出不对。

## 3. 优化后的产品功能设计

> 本章描述本计划目标，不代表当前已实现。当前状态只看第 4 节；最终产品契约只看第 0 节。

### 3.1 信息架构

应用采用“三层能力”设计：

- 基础模式：导入图片、选择版式、微调边框和文字、导出。
- 效率模式：批量导入、每图文字覆盖、EXIF 自动填充、版式保存、批量导出。
- 专业模式：TIFF、16-bit、ICC、元数据复制、高保真预览和导出。

其中，专业模式属于本计划目标，不得在当前状态中写成已经支持。阶段 0 先冻结本节
契约，再按样片矩阵实现和验收本地安装、图片导入、数码 EXIF、拍摄信息预设、版式和
批量导出闭环。

### 3.2 首屏流程

优先推荐两种入口：

- 快速开始：添加图片后自动进入工作台，使用默认版式。
- 版式入口：先选择版式，再导入图片或应用到当前图片。

首批内置版式建议：

- 经典白边：适合多数照片，底部信息栏。
- 极简黑边：黑底白字，适合夜景和高反差图。
- 宽边留白：大留白、杂志感。
- 拍立得：底部加宽，可加入手写签名。
- 毛玻璃背景：图片模糊铺底，主体居中。
- 圆角阴影：现代卡片风格。
- 拍摄信息条：相机/镜头/胶片或 EXIF 参数 + 日期。
- 全画幅叠字：文字叠加在图片上。

### 3.3 图片导入

本计划目标必须遵守 §0.2 的输入格式契约：

- 单张导入。
- 批量导入。
- 队列缩略图。
- 队列选中切换。
- 队列删除。
- 拖拽导入。
- JPEG、PNG、TIFF、HEIC/HEIF 导入。
- RAW 只读取内嵌 JPEG 预览；没有可读取内嵌 JPEG 时明确失败。

待规划能力（不改变本阶段统一工作台范围）：

- 队列右键菜单：关闭当前、关闭其他、关闭左侧、关闭右侧、全部关闭。

HEIC/HEIF 和 RAW 的“代码路径存在”不等于“最终支持”。只有在 macOS arm64、macOS x64
和 Windows x64 上通过 [`docs/test-samples.md`](test-samples.md) 的样片矩阵，才可以对外
宣称正式支持。WebP、BMP 不纳入最终输入格式。

### 3.4 边框与背景

基础能力：

- 上、下、左、右边框独立设置。
- 纯色边框。
- 线性渐变。
- 径向渐变。
- 多停靠点渐变。
- 圆角。
- 图片阴影。
- 图片放在边框上或背景上。

进阶能力：

- 内边距和外边距。
- 主边框和副边框。
- 毛玻璃背景：原图模糊铺底，可调模糊和亮度。
- 背景模式：无背景、纯色、图片模糊、渐变。
- 边框样式：实线、虚线、点线。

### 3.11 拍摄信息预设工作流

拍摄信息预设解决的是“没有完整 EXIF 时，快速给照片补齐可展示的拍摄身份”，不承担
胶卷、冲洗或扫描管理。

数码流程：

1. 导入图片。
2. 自动读取 EXIF，并把相机、镜头、曝光和拍摄时间填入信息模型。
3. 用户可选拍摄信息预设补充拍摄画幅、默认地点或修正设备名称。
4. 应用版式并预览、导出。

胶片流程：

1. 创建或选择一个拍摄信息预设。
2. 选择分类，并填写相机、镜头、胶片和拍摄画幅。
3. 将拍摄信息预设应用到当前图片、选中图片或全部图片。
4. 对单张图片补充地点、帧号和自定义文本。
5. 应用版式并批量导出。

字段优先级固定为：每图覆盖 > 拍摄信息预设 > EXIF > 空。拍摄信息预设、版式与图片队列是
三个独立对象，删除拍摄信息预设不会删除图片，也不会让版式失效。

### 3.12 Contact Sheet 接触表（延期）

Contact Sheet 是可选的后续展示能力，不属于当前摄影信息边框 MVP。未来若实现，应以图片列表和通用摄影信息为输入，不引入 Roll、冲洗、扫描或实验室对象。

### 3.13 暗房和档案馆风格版式（延期）

这类版式可以作为后续视觉扩展，但不是当前版本的交付前置条件。首版先覆盖通用边框、拍摄信息条、极简和分享场景。

### 3.14 导出

本计划目标固定为 §0.3 的三个导出档位：快速分享、标准交付、高保真归档。档位名称、
格式、质量、尺寸、位深、色彩和元数据策略不得在实现阶段自行变更。PNG 8-bit/16-bit
必须作为 §0.3 定义的同档位输出格式变体提供，不得新增第四个档位；前端必须展示档位、
输出格式、位深、尺寸、色彩和元数据结果，并拒绝未定义的档位/格式组合。

当前实现中的“原图 / 1080P / 2K / 4K / 自定义长边”等尺寸控件不属于冻结契约；在完成
产品实现前，不得把它们写成最终导出档位。导出不能覆盖原图，导出结果必须有明确的
成功/失败状态和实际格式说明。

导出原则：

- 快速分享的长边为 2048（源图更小则不放大），输出为 sRGB，并移除 GPS/位置。
- 标准交付保持原图尺寸、8-bit、源 ICC 和全部元数据，包含 GPS/位置。
- 高保真归档保持原图尺寸、源位深（8/16-bit）、源 ICC 和全部元数据，包含 GPS/位置。
- 所有影响画质、尺寸、色彩或元数据的结果必须在导出前和结果中明确展示。

导出保真报告（本计划目标）：

- 原图格式、尺寸、位深、ICC、EXIF、XMP、IPTC、GPS。
- 导出格式、尺寸、位深、ICC、EXIF、XMP、IPTC、GPS。
- 保留结果：完整保留、部分保留、未保留。
- 差异说明：尺寸变化、格式变化、JPEG 压缩、元数据不支持、ICC 丢失、GPS/位置移除等。
- 报告可复制为文本，方便用户反馈问题。

### 3.15 预览

普通预览：

- 使用缩略图链路，保证交互实时。
- 设置修改后自动刷新。
- Canvas 即时预览优先，后端引擎同步校验。

高保真预览：

- 使用 PNG 或无损链路。
- 尽量接近导出结果。
- 对大图进行受控缩放，避免内存爆炸。

交互能力：

- 预览缩放。
- 预览拖拽。
- 适应屏幕。
- 网格辅助。
- 显示当前预览是否已同步引擎。

### 3.16 色彩一致性与元数据测试规范

专业摄影用户最怕“不知道软件动了什么”。项目需要建立可验证的质量标准。

色彩一致性测试：

- 对无色彩效果的导出进行像素或采样点比对。
- 快速分享在转换到 sRGB 后记录色彩转换结果；JPEG 压缩误差单独记录。
- 标准交付必须记录源 ICC 与输出 ICC 是否一致；输出位深固定为 8-bit。
- 高保真归档必须记录源 ICC 与输出 ICC 是否一致，以及源位深与输出位深是否一致。
- 若使用像素或 ΔE 指标，阈值和测量方式必须随测试记录，不得用未落地的阈值宣称已达标。

元数据测试：

- 对比 EXIF、XMP、IPTC、GPS/位置及目标容器可承载的其他元数据是否保留。
- 快速分享必须确认 GPS/位置已移除；标准交付和高保真归档必须确认 GPS/位置保留。
- 明确哪些字段被移除、哪些字段被重写、哪些字段因源图不存在而未生成。
- 尺寸、方向、缩略图等不应继承的字段要有白名单/黑名单策略。

样片矩阵：

- 格式、位深、ICC、EXIF/XMP/IPTC/GPS 组合及每档预期结果统一维护在
  [`docs/test-samples.md`](test-samples.md)，本节不再复制另一份易漂移的清单。
- 矩阵必须覆盖 JPEG、PNG、TIFF、HEIC、HEIF、带内嵌 JPEG 的 RAW，以及无内嵌 JPEG 的
  RAW 失败路径；必须同时覆盖 8-bit、16-bit、有 ICC、无 ICC、有元数据和无元数据。

回归要求：

- 每次修改渲染、导出、元数据相关代码，都要按三个固定导出档位跑样片回归。
- 如果导出报告变化，必须在变更说明中解释。

### 3.17 AI 增强能力

AI 功能放入 V2 付费规划，不进入免费 MVP。AI 的定位是“生成建议和自动化配置”，不是替代确定性渲染引擎。最终导出仍由 Java Engine 根据结构化参数执行，保证结果可控、可复现、可测试。

V2 付费 AI 能力：

- 智能版式推荐：根据照片横竖构图、明暗、色调、主体位置推荐白边、黑边、毛玻璃、拍立得、全画幅叠字等版式。
- 智能配色：从照片提取主色和辅助色，推荐边框色、渐变色、文字色和 Logo 深浅版本。
- 智能排版建议：识别主体安全区，避免文字压住人脸、建筑主体、天空亮部或画面视觉中心。
- 摄影信息文案生成：根据 EXIF 和用户设备库生成简洁参数文案或更有氛围感的标题、日期、签名。
- 批量智能套版：批量导入后自动按横图/竖图、明亮/暗调、人像/风景分组，并套用不同版式。
- 导出前智能检查：提示文字太小、对比度不足、边框过厚、裁剪可能切主体、Logo 和背景撞色等问题。
- EXIF 缺失补全助手：根据用户常用设备、文件名和手动输入生成候选参数，需用户确认后才写入文字或版式。

AI 使用边界：

- 默认关闭，用户主动启用。
- 免费 MVP 不依赖 AI，离线基础功能必须完整可用。
- AI 不直接输出最终图片，不直接修改原图。
- AI 只生成可编辑的版式参数、文字建议、颜色建议和风险提示。
- 如果需要云端模型，只上传低分辨率预览图和必要 EXIF，上传前必须明确提示。
- 后续可探索本地轻量模型，但不作为 V2 首要前提。

## 5. 技术架构

### 5.1 总体架构

- Electron 主进程负责应用生命周期、文件选择、保存目录选择、版式本地存储和打包；自动更新不属于最终产品职责。
- React 渲染进程负责界面交互、状态编排、Canvas 即时预览。
- Java Engine 负责高质量图片读取、合成、导出、EXIF/ICC/TIFF/16-bit 等专业图像能力。
- 前端通过 localhost HTTP 调用 Java Engine。

### 5.2 为什么不采用 DOM 截图作为核心导出

DOM/CSS 模板适合快速做复杂视觉样式，但它的输出本质更接近屏幕截图，不适合作为本项目的专业高保真导出核心。最终导出仍应走 Java 图像引擎。

可以吸收 DOM 模板思想，但落地方式应是：

- 前端用版式预览和编辑。
- 后端用结构化 recipe 渲染。
- 版式最终必须能转换为可验证的 RenderRecipe。

### 5.3 模块规划

Electron：

- `main`：主窗口和生命周期。
- `preload`：安全 API 暴露。
- `ipc`：文件选择、目录选择、版式存储、未来系统字体读取。

## 7. API 规划

> 端点与字段的**权威定义以 `java-engine/src/main/java/com/camborder/app/controller/` 源码为准**，此处仅为产品视角索引，会随实现漂移。改动 API 前先读 [ARCHITECTURE.md §4（API 设计规则）](../ARCHITECTURE.md)。

现有 API（截至本文档成稿）：

- `GET /api/health`
- `GET /api/dev/photos`（样片浏览器，扫描仓库根 `photos/`）
- `POST /api/preview`
- `GET /previews/{id}`
- `POST /api/render-jobs`（提交 1–100 个冻结快照，返回 `202 + jobId`；不等待渲染完成）
- `GET /api/render-jobs/{jobId}`（查询总进度、当前项、逐项结果和失败原因）
- `DELETE /api/render-jobs/{jobId}`（取消尚未执行的项；正在执行的项自然收尾）
- `GET /api/film-formats`（拍摄画幅枚举 + 边框布局建议：数码 M43/APS-C/135 全画幅/4433，胶片半格/135/645/6×6/6×7/6×8/6×9/6×10/6×12；产品模型逐步统一为 capture formats）
- `POST /api/photo-metadata`
- `GET /api/fonts`（可用字体与内置字体）
- `GET /api/assets/film-stocks`（内置胶片库，可选能力）
- `POST /api/metadata/format`（EXIF 字段格式化为展示文本）

建议新增 API（roadmap）：

- `GET /api/capture-formats`：返回数码与胶片拍摄画幅及比例/边框建议；不执行裁剪。
- `GET /api/logos`：返回品牌 Logo 清单。
- `GET /api/output-presets`：返回三个固定导出档位（快速分享、标准交付、高保真归档）；不返回未在 §0.3 定义的尺寸档位。
- `POST /api/templates/validate`：校验版式 JSON 是否可用。
- 不另设批量端点：单个 `POST /api/render-jobs` 的 `items` 数组同时覆盖单图和批量导出。
- `POST /api/contact-sheets`：生成 Contact Sheet（延期能力，不进入 MVP）。
- `GET /api/render-jobs/{jobId}/fidelity-report`：获取导出保真报告。
- `POST /api/fidelity/compare`：对比原图和导出图的色彩与元数据差异。

## 8. 阶段计划

### 阶段 1：可安装的摄影师 MVP（本计划目标）

目标：让用户在 macOS arm64、macOS x64 和 Windows x64 上无需登录、无需安装 Java，即可
完成“导入 → 识别/补充拍摄信息 → 套版式 → 预览 → 批量导出”。输入、输出和导出档位
必须遵守 §0，不以本阶段的代码完成度倒推产品支持。

任务：

- 固化数码与胶片拍摄画幅模型：M43、APS-C、135 全画幅、4433 中画幅，以及半格、135、645、6x6、6x7、6x8、6x9、6x10、6x12；6x12 保留，不以 6x10 替换。
- 完善数码 EXIF 读取、字段标准化和缺失值处理。
- 实现相机、镜头、胶片三类本地资产库。
- 实现可分类的拍摄信息预设：创建、编辑、复制、删除、应用到单张/选中/全部图片。
- 实现字段优先级：每图覆盖 > 拍摄信息预设 > EXIF > 空。
- 收敛版式与拍摄信息预设的边界，版式只负责排版，拍摄信息预设只负责拍摄身份。
- 完善拖拽导入、队列删除、单图预览、单图导出和批量导出。
- 保证 Canvas 预览、引擎预览、单图导出、批量导出共用同一套 RenderRecipe。
- 记录导出失败原因，支持失败项重试和导出后打开目录。
- 完成 Electron 托管 Java Engine、运行时路径、日志和异常恢复。
- 使用 electron-builder 产出 macOS arm64、macOS x64 的 `.dmg` 和 Windows x64 的 `.exe`，内置 Java Runtime 和 Java Engine。

验收：

- 新用户在三种最终平台的干净环境安装后可以直接启动，不要求登录、不要求安装 Java。
- 数码图片导入后可直接看到 EXIF 信息；胶片图片可通过分类拍摄信息预设补齐信息。
- 拍摄画幅覆盖产品清单，且不会默认裁剪或改变原图尺寸；只产生边框布局建议。
- 预览与导出在文字、边框、渐变、拍摄信息上保持一致。
- 三个固定导出档位和样片矩阵全部通过后，才可宣称格式、位深、ICC 和元数据正式支持。
- 单图和批量导出均能明确展示成功/失败状态，原图不会被覆盖。

### 阶段 2：效率与排版增强

目标：减少重复操作，让摄影师能更快地完成一组照片的统一出图和个别修正。

本阶段当前实现的稳定性基线包括：异步 `render-jobs` 有界队列、根级导出控制器、独立的
`active / checked / all` 作用域、队列与设置撤销/重做、工作会话恢复及丢失文件标记；预览与
缩略图按目标尺寸解码、缩略图最多双并发、预览只保留最新请求，缓存按路径/尺寸/mtime/源字节数/
配方哈希隔离并受字节预算约束。性能 smoke 用 `pnpm perf:smoke` 执行，前置为本机 Java 引擎已启动。

验收：

- 用户可明确选择“当前图片/选中图片/全部图片”的作用范围。
- 统一设置与单图覆盖互不误伤，重新选择图片后状态可解释。

## 10. 设计原则

- 默认不破坏原图色彩。
- 默认导出原图尺寸。
- 所有会影响画质、尺寸、色彩、元数据的选项都必须明确展示。
- 预览快，导出准。
- 版式可以漂亮，但底层数据必须结构化。
- 专业能力分阶段做，不在当前实现阶段假装完整支持。
- 数码优先读取 EXIF，胶片通过可分类拍摄信息预设补充，不强迫两者使用同一套录入流程。
- 拍摄信息预设、版式和图片队列职责分离；删除一个对象不能产生隐式级联删除。
- 本地优先且无需登录，应用离线时核心导入、排版和导出仍可用。
- 所有用户可见文案使用简体中文。
- 项目结构保持清晰，按功能域组织，避免文件随意堆叠。

## 11. 验收标准

### 阶段 0 / 最终产品契约验收

- 最终平台仅为 macOS arm64、macOS x64、Windows x64。
- 输入覆盖 JPEG、PNG、TIFF、HEIC/HEIF，以及只读取内嵌 JPEG 预览的 RAW；RAW 不做真实显影。
- 输出覆盖 JPEG 8-bit、PNG 8/16-bit、TIFF 8/16-bit。
- 快速分享、标准交付、高保真归档三个导出档位严格符合 §0.3。
- 快速分享移除 GPS/位置；标准交付和高保真归档保留 GPS/位置。
- 样片矩阵覆盖每种格式、位深、ICC 和元数据组合，并覆盖 RAW 无内嵌 JPEG 的失败路径。
- 修图、云同步、登录、自动更新和真实 RAW 显影不在产品范围内。

### MVP 验收（以 §4 当前状态为准，不自动等同于最终支持）

- 可导入单张和多张图片。
- 可设置边框、渐变、文字和拍摄画幅。
- 可保存、加载、导入、导出版式。
- 可批量导出 JPEG/PNG。
- 数码照片可使用 EXIF 自动填充文字和拍摄信息。
- 胶片照片可通过可分类拍摄信息预设补充相机、镜头、胶片和拍摄画幅。
- 支持相机、镜头、胶片三类资产库。
- 字段优先级为每图覆盖 > 拍摄信息预设 > EXIF > 空。
- 覆盖半格、135、645、6x6、6x7、6x8、6x9、6x10、6x12 以及 M43、APS-C、135 全画幅、4433 中画幅。
- 三种最终平台的安装包可在无 Java 环境下启动。
- 不要求登录，图片和本地资产不离开用户电脑。
- 预览与导出整体一致。
- Electron 模式可日常使用，导出失败有明确反馈且不会覆盖原图。

### 后续排版增强验收（不改变 §0 契约）

- 至少 8 套内置版式。
- 支持 Logo 自动识别。
- 支持多段文字和变量插入。
- 支持版式卡片、预览缩放和裁剪拖动。
- 支持更丰富的批量作用域；不得借此增加第四个导出档位。

### 高保真目标验收（当前未完成）

- 支持源 ICC 保留。
- 支持 TIFF 8/16-bit，并按档位保持源位深。
- 支持 EXIF/XMP/IPTC/GPS 全部元数据继承；快速分享例外为移除 GPS/位置。
- 有覆盖格式、位深、ICC、元数据的样片测试和元数据对比结果。
