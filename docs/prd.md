# 图片边框工具项目文档（PRD 与路线图）

> 本文档整合原 PRD、当前项目实现状态，以及对 Copicseal、远山、Polaroid Style Generator、PhotoBorderMasker、OneFrame 等同类项目的功能分析。目标是把本项目收敛为一款面向摄影用户的本地桌面图片边框工具，并明确后续功能优先级。
>
> **文档角色**：本文件是产品 PRD 与路线图，回答「做什么、为什么做、分阶段怎么做」。当前功能实现状态与运行方式以 [README](../README.md) 为准；架构约束与边界见 [ARCHITECTURE.md](../ARCHITECTURE.md)；开发环境、命令与验证路径见 [CONTRIBUTING.md](../CONTRIBUTING.md)；关键取舍的原因见 [docs/adr/](adr/)。

## 1. 产品定位

### 1.1 产品一句话

面向数码与胶片摄影用户的本地桌面图片边框工具，支持读取数码 EXIF、用胶片摄影预设补充拍摄信息、添加高质量边框与模板样式，并批量导出成品。应用最终以 Windows `.exe` 和 macOS `.dmg` 交付，不要求登录。

### 1.2 目标用户

- 数码摄影用户
- 胶片摄影用户
- 摄影博主和内容创作者
- 需要批量出图的摄影工作室
- 对 TIFF、ICC、EXIF、16-bit 有要求的进阶摄影用户

### 1.3 核心价值

- 快速生成适合社交平台和作品展示的照片边框。
- 数码照片自动读取并排版相机、镜头、光圈、快门、ISO、焦距等 EXIF 信息。
- 胶片照片通过可分类的摄影预设补充相机、镜头、胶片和画幅等信息。
- 支持模板复用和批量导出，减少重复劳动。
- 在专业模式下尽量保留原图分辨率、色彩空间、位深和元数据。

### 1.4 产品边界

首版不做完整修图软件，不做登录、云同步、移动端和在线模板商店。首版也不做 Roll、冲洗、扫描、实验室或暗房工作流。项目重点是“边框、文字、摄影信息、模板、批量、高质量导出”，并保证在 Windows 和 macOS 上可安装运行。

## 2. 竞品与参考项目分析

### 2.1 Copicseal

项目地址：https://github.com/copicseal/copicseal

定位：模板化相框和水印生成器。

优点：

- 已经是完整 Electron 桌面应用，具备打包、发布、自动更新配置。
- 模板表达力强，模板本质是 Vue/CSS 组件，可以做白边、圆角、PS 启动窗、时间戳、内嵌文字、重复水印等复杂版式。
- EXIF 变量系统成熟，可用 `{FocalLength}`、`{FNumber}`、`{ExposureTime}`、`{ISOSpeedRatings}` 等变量拼接文字。
- 支持系统字体读取、全局字体选择、输出尺寸预设、批量导出、导出进度。
- 支持相机/镜头设备预设，可快速覆盖当前图片参数。
- 使用 exiftool 写回部分元数据，说明元数据保留是用户真实需要。

可吸收设计：

- 文本变量插入器。
- 系统字体读取与字体收藏。
- 输出尺寸预设。
- 设备预设库。
- 模板卡片和模板参数自动生成面板。
- 发布打包和自动更新链路。

不建议照搬：

- 它的最终导出依赖 DOM/Puppeteer 截图，适合模板表达，但不适合本项目长期追求 TIFF、16-bit、ICC 的高保真路线。

### 2.2 远山 yuanshan

项目地址：https://github.com/lozyHao/yuanshan

定位：照片边框、水印、参数展示和配置分享工具。

优点：

- 支持自定义边框、背景、图片、文字、水印样式。
- 参数修改后自动实时预览，强调防抖刷新。
- 内置 6 套常用风格模板，如经典模糊、纯白边框、极简黑框、宽边留白、圆角阴影、底部信息条。
- 支持配置导入/导出，把基础配置、文字模板、相机参数整合成 JSON，方便迁移和分享。
- 支持相机自带参数编辑、新增和手动修正。
- 支持预览图拖拽/缩放，方便查看细节。
- 有字体转图片、画板等辅助工具，说明“签名/花字/手写感”有用户价值。
- Canvas 绘制中包含圆角、投影、模糊背景、水印位置、文字背景、主边框/副边框等细节。

可吸收设计：

- 预设模板首屏卡片化。
- 配置导入/导出 JSON。
- 背景模糊和毛玻璃风格。
- 圆角、投影、文字背景、水印图层。
- 预览缩放/拖拽。
- 字体签名转图片或手写签名素材。

### 2.3 Polaroid Style Generator

项目地址：https://github.com/Sacilave/polaroid-style-generator

定位：拍立得框架和复古胶片效果生成器。

优点：

- 框架和色彩效果分离，架构简单清晰。
- 支持 original、polaroid、symmetric 三种框架。
- 拍立得边框比例明确：左右和顶部按宽度比例计算，底部加宽。
- 支持复古、黑白胶片、即时显影、交叉冲洗、电影胶片、复古彩色等多组色彩效果。
- 支持随机组合、一键生成所有组合。
- 使用颗粒感、饱和度、对比度、色温等简单参数实现胶片氛围。

可吸收设计：

- 拍立得模板作为首批视觉模板之一。
- 胶片色彩预设作为可选效果，但默认不改变原图。
- “框架预设”和“色彩预设”分离，避免模板系统混乱。
- 随机预览/随机组合可作为后续创意功能。

注意：

- 它会改变照片色彩，本项目应把这类能力放到“创意模式”，不能影响高保真导出默认值。

### 2.4 PhotoBorderMasker

项目地址：https://github.com/WekyJay/PhotoBorderMasker

定位：基于 Konva 的图片边框和 EXIF 信息可视化编辑器。

优点：

- 使用 Konva 提供可拖拽、可选中、可复制、可删除的图层编辑体验。
- 支持网格、适应屏幕、右键菜单、元素选择提示。
- 边框模型包含 thickness、top、right、bottom、left、innerPadding、outerPadding、color、radius、style。
- 支持自定义文字元素、矩形元素、品牌 Logo、EXIF 参数文本。
- 模板支持保存、复制、删除、导入、导出 JSON。
- 支持拖拽 JSON 模板文件直接应用。
- EXIF 字段可拖拽到画布或文本中。

可吸收设计：

- 进阶模板编辑器可以采用“图层/元素”模型。
- 模板 JSON 应包含 border、items、text、logo、metadata 这些结构化数据。
- EXIF 字段拖拽插入文本，是很适合摄影用户的交互。
- 右键菜单和网格辅助能明显提升编辑效率。

阶段建议：

- MVP 不需要完整 Konva 编辑器。
- V2 可加入“高级模板编辑器”，允许自由拖放文字、Logo、矩形和装饰元素。

### 2.5 OneFrame

项目地址：https://github.com/IceyVanci/OneFrame

定位：多样式摄影信息边框桌面工具。

优点：

- 首页以 Type A-H 样式卡片展示，用户先选风格再导入图片，路径很清晰。
- 样式覆盖白色下边框、黑色下边框、横向布局、Logo 居中布局、1:1 裁剪、画中画、居中参数、全画幅叠加文字。
- 自动识别相机厂商并显示 Logo。
- 支持 Logo 显示开关、参数显示开关、拍摄时间显示开关、自定义署名。
- 部分样式支持拖动裁剪。
- 导出时保留 JPG EXIF，使用预览模块和导出模块双轨，强调预览与导出一致。
- 有较完整的样式注册表，预览、导出、编辑面板按样式拆分。

可吸收设计：

- 首页提供“样式选择”入口，而不是只给参数面板。
- 内置 6-8 个首批模板，按视觉用途命名。
- 相机品牌 Logo 自动识别和深浅背景自动适配。
- 每个模板可以有自己的参数面板。
- 预览模块和导出模块共享布局计算，避免看起来对、导出不对。

## 3. 优化后的产品功能设计

### 3.1 信息架构

应用采用“三层能力”设计：

- 基础模式：导入图片、选择模板、微调边框和文字、导出。
- 效率模式：批量导入、每图文字覆盖、EXIF 自动填充、模板保存、批量导出。
- 专业模式：TIFF、16-bit、ICC、元数据复制、高保真预览和导出。

其中，专业模式属于后续能力；MVP 必须先把本地安装、图片导入、数码 EXIF、胶片摄影预设、模板和批量导出闭环做稳定。

### 3.2 首屏流程

优先推荐两种入口：

- 快速开始：添加图片后自动进入工作台，使用默认模板。
- 样式模板：先选择视觉模板，再导入图片或应用到当前图片。

首批内置模板建议：

- 经典白边：适合多数照片，底部信息栏。
- 极简黑边：黑底白字，适合夜景和高反差图。
- 宽边留白：大留白、杂志感。
- 拍立得：底部加宽，可加入手写签名。
- 毛玻璃背景：图片模糊铺底，主体居中。
- 圆角阴影：现代卡片风格。
- 摄影信息条：相机/镜头/胶片或 EXIF 参数 + 日期。
- 全画幅叠字：文字叠加在图片上。

### 3.3 图片导入

MVP 支持：

- 单张导入。
- 批量导入。
- 队列缩略图。
- 队列选中切换。
- 队列删除。
- 拖拽导入。

后续支持：

- 队列右键菜单：关闭当前、关闭其他、关闭左侧、关闭右侧、全部关闭。
- HEIC/HEIF 预览转换。
- RAW/HEIC 的正式支持范围需单独验证，不作为本轮 MVP 的必需条件。

支持格式：

- MVP：jpg、jpeg、png、tif、tiff 读取；png/jpg/jpeg 导出。
- V2：TIFF 导出、16-bit PNG/TIFF、ICC 保留。

### 3.4 边框与背景

基础能力：

- 上、下、左、右边框独立设置。
- 纯色边框。
- 线性渐变。
- 径向渐变。
- 多停靠点渐变。
- 圆角。
- 图片阴影。
- 图片放在边框上或背景上。

进阶能力：

- 内边距和外边距。
- 主边框和副边框。
- 毛玻璃背景：原图模糊铺底，可调模糊和亮度。
- 背景模式：无背景、纯色、图片模糊、渐变。
- 边框样式：实线、虚线、点线。

### 3.5 文字与摄影信息

MVP 支持：

- 单段文字。
- 放在图片上或边框上。
- 顶部居中、居中、底部居中、边框顶部、边框底部。
- 字体、字号、颜色。
- 每张图独立文字覆盖。
- EXIF 自动填充基础文本。

V1.5 支持：

- 多段文字。
- 左、中、右三栏布局。
- 文字变量插入器。
- 文字模板保存。
- 行距、字距、边距。
- 文字背景条。
- 阴影和描边。
- 横排和竖排。

推荐变量：

- `{Make}` 相机厂商。
- `{Model}` 相机型号。
- `{Camera}` 相机名称，可来自 EXIF、摄影资产库或摄影预设。
- `{Lens}` 镜头名称，可来自 EXIF、摄影资产库或摄影预设。
- `{LensModel}` 镜头型号。
- `{FocalLength}` 焦距。
- `{FNumber}` 光圈。
- `{ExposureTime}` 快门。
- `{ISO}` 感光度。
- `{DateTimeOriginal}` 拍摄时间。
- `{CaptureFormat}` 拍摄画幅，例如 M43、APS-C、135、645。
- `{FilmName}` 胶片名称。
- `{Film}` 胶片名称，推荐替代 `{FilmName}`。
- `{FilmBrand}` 胶片品牌。
- `{FilmIso}` 胶片标称 ISO。
- `{FilmType}` 胶片类型，例如彩色负片、黑白负片、反转片。
- `{FrameNumber}` 当前张编号。
- `{Location}` 拍摄地点。
- `{CustomText}` 自定义文本。

### 3.6 Logo 与品牌识别

功能设计：

- 自动根据 EXIF Make 识别相机品牌。
- 支持显示或隐藏品牌 Logo。
- 支持相机 Logo、镜头 Logo、胶片 Logo。
- 深色背景自动使用浅色 Logo，浅色背景使用深色 Logo。
- 找不到 Logo 时回退为品牌文字。

首批品牌：

- Apple、Canon、DJI、Fujifilm、GoPro、Hasselblad、Leica、Lumix、Nikon、Olympus、Pentax、Ricoh、Sigma、Sony、Xiaomi。

### 3.6.1 摄影作品身份

数码照片主要依赖 EXIF，胶片照片主要依赖摄影预设。产品应支持一张照片同时表达：

- 相机：例如 Leica M6、Pentax 67、Nikon F3。
- 镜头：例如 Voigtlander 35mm F1.4、SMC Takumar 105mm F2.4。
- 胶片：例如 Kodak Gold 200、Portra 400、Cinestill 800T。
- 拍摄画幅：例如 M43、APS-C、135、645、6x6。
- 地点和帧号：由用户在每张图片上补充。

设计原则：

- 这些字段默认只用于展示和模板排版，不修改原图元数据。
- 数码图片优先使用 EXIF；胶片图片通过摄影预设批量应用。
- 用户可以把预设应用到当前图片、选中图片或全部图片。
- EXIF 或预设缺失的字段必须允许每张图片手动覆盖。
- 不在首版引入 Roll、冲洗、扫描、实验室等字段，避免用户为导出边框承担暗房管理成本。

### 3.7 拍摄画幅与比例

数字摄影画幅：

- M43：通常为 4:3。
- APS-C：通常为 3:2。
- 135 全画幅：通常为 3:2。
- 4433 中画幅：通常为 4:3。

胶片画幅：

- 半格。
- 135。
- 645。
- 6x6。
- 6x7。
- 6x8。
- 6x9。
- 6x10。
- 6x12（保留的超宽画幅）。

支持行为：

- 切换画幅自动填充推荐边框值和信息展示建议。
- 用户可手动覆盖。
- 画幅预设与图片裁剪解耦；需要裁剪时必须由用户明确开启。
- 画幅只影响布局建议，不强行改变用户设置、原图比例或导出尺寸。

### 3.8 色彩效果

默认不改图色彩。

后续创意模式可选：

- 复古褪色。
- 经典黑白。
- 高对比黑白。
- 柔和黑白。
- 70s/80s/90s 即时显影。
- 柯达电影感。
- 富士清爽感。
- Vision3 自然电影感。
- 交叉冲洗。
- 颗粒感。

规则：

- 色彩效果必须可关闭。
- 导出时必须明确标注“将改变原图色彩”。
- 高保真模式禁用色彩效果，除非用户明确确认。

色彩效果不是摄影信息边框 MVP 的交付前置条件，首版可不提供。

### 3.9 模板系统

模板分三类：

- 参数模板：保存边框、文字、渐变、导出设置。
- 视觉模板：保存布局风格和可调参数。
- 批量模板：保存全局样式和每图文字规则。

模板能力：

- 保存当前设置为模板。
- 加载模板。
- 设置默认模板。
- 复制模板。
- 删除模板。
- 导入模板 JSON。
- 导出模板 JSON。
- 拖拽 JSON 模板直接应用。
- 模板缩略图预览。

模板字段建议：

```json
{
  "id": "white-frame",
  "name": "经典白边",
  "version": 1,
  "layout": "classic-info-bar",
  "border": {},
  "background": {},
  "gradient": {},
  "texts": [],
  "logos": [],
  "captureFormat": "film-135",
  "export": {},
  "metadata": {}
}
```

### 3.10 摄影资产库与摄影预设

功能设计：

- 用户可新增相机、镜头、胶片三类资产。
- 用户可创建摄影预设，并为预设设置分类，例如“数码常用”“135 胶片”“中画幅胶片”“旅行”。
- 摄影预设可以引用相机、镜头、胶片资产，并附带拍摄画幅。
- 可把预设应用到当前图片、选中图片或全部图片。
- 支持用每张图片的手动字段覆盖 EXIF 或摄影预设。
- 支持复制当前图片 EXIF JSON，方便调试。

资产类型：

- 相机：品牌、型号、别名、备注。
- 镜头：品牌、型号、焦段、最大光圈、卡口、备注。
- 胶片：品牌、名称、ISO、类型、色彩倾向、停产状态、备注。

摄影预设字段：

- 名称、分类。
- 拍摄画幅。
- 相机资产、镜头资产、胶片资产，可为空。
- 可选默认地点和备注。

内置库首版不追求完整，先提供用户自定义能力。后续可内置常见胶片库：

- Kodak Gold 200、Portra 160、Portra 400、Portra 800、Ektar 100、Tri-X 400。
- Fujifilm C200、Fujifilm 100、Pro 400H、Acros 100。
- Cinestill 400D、Cinestill 800T。
- Ilford HP5 Plus、FP4 Plus、Delta 400。

### 3.11 摄影预设工作流

摄影预设解决的是“没有完整 EXIF 时，快速给照片补齐可展示的拍摄身份”，不承担胶卷、冲洗或扫描管理。

数码流程：

1. 导入图片。
2. 自动读取 EXIF，并把相机、镜头、曝光和拍摄时间填入信息模型。
3. 用户可选摄影预设补充画幅、默认地点或修正设备名称。
4. 应用视觉模板并预览、导出。

胶片流程：

1. 创建或选择一个摄影预设。
2. 选择分类，并填写相机、镜头、胶片和拍摄画幅。
3. 将预设应用到当前图片、选中图片或全部图片。
4. 对单张图片补充地点、帧号和自定义文本。
5. 应用视觉模板并批量导出。

字段优先级固定为：每图覆盖 > 摄影预设 > EXIF > 空。预设、模板与图片队列是三个独立对象，删除预设不会删除图片，也不会让模板失效。

### 3.12 Contact Sheet 接触表（延期）

Contact Sheet 是可选的后续展示能力，不属于当前摄影信息边框 MVP。未来若实现，应以图片列表和通用摄影信息为输入，不引入 Roll、冲洗、扫描或实验室对象。

### 3.13 暗房和档案馆风格模板（延期）

这类模板可以作为后续视觉扩展，但不是当前版本的交付前置条件。首版先覆盖通用边框、摄影信息条、极简和分享场景。

### 3.14 导出

MVP：

- 单图导出。
- 批量导出。
- PNG。
- JPEG。
- JPEG 质量设置。
- 文件名冲突处理。
- 原图尺寸导出。
- 导出进度展示。

V2：

- TIFF 导出。
- 16-bit PNG/TIFF。
- 保留 ICC Profile。
- 复制 EXIF/XMP/IPTC/GPS。
- 保留或写入 DPI。
- 导出后打开目录。
- 导出预设：原图、1080P、2K、4K、小红书、朋友圈、自定义尺寸。
- 导出保真报告。

导出原则：

- 默认使用原图尺寸，不偷偷压缩。
- 如果用户选择社交平台尺寸，必须明确显示输出尺寸。
- 如果导出体积明显变小，要能解释是格式、质量、尺寸还是元数据变化导致。
- 导出完成后应告诉用户保留了什么、丢失了什么。

导出保真报告：

- 原图格式、尺寸、位深、ICC、EXIF、XMP、IPTC、GPS。
- 导出格式、尺寸、位深、ICC、EXIF、XMP、IPTC、GPS。
- 保留结果：完整保留、部分保留、未保留。
- 差异说明：尺寸变化、格式变化、JPEG 压缩、元数据不支持、ICC 丢失等。
- 报告可复制为文本，方便用户反馈问题。

### 3.15 预览

普通预览：

- 使用缩略图链路，保证交互实时。
- 设置修改后自动刷新。
- Canvas 即时预览优先，后端引擎同步校验。

高保真预览：

- 使用 PNG 或无损链路。
- 尽量接近导出结果。
- 对大图进行受控缩放，避免内存爆炸。

交互能力：

- 预览缩放。
- 预览拖拽。
- 适应屏幕。
- 网格辅助。
- 显示当前预览是否已同步引擎。

### 3.16 色彩一致性与元数据测试规范

专业摄影用户最怕“不知道软件动了什么”。项目需要建立可验证的质量标准。

色彩一致性测试：

- 对无色彩效果的导出进行像素或采样点比对。
- 普通 8-bit JPEG/PNG 链路允许 RGB 通道误差不超过 1，JPEG 压缩场景单独记录。
- 高保真模式优先使用 ΔE 指标，目标 ΔE 小于 1。
- ICC 保留测试必须记录原图和导出图的 ICC Profile 是否一致。

元数据测试：

- 对比 EXIF、XMP、IPTC、GPS 是否保留。
- 明确哪些字段被移除，哪些字段被重写。
- 尺寸、方向、缩略图等不应继承的字段要有白名单/黑名单策略。

样片库：

- JPEG sRGB。
- JPEG Adobe RGB。
- TIFF 8-bit。
- TIFF 16-bit。
- 带 GPS 的样片。
- 带 XMP/IPTC 的样片。
- 无 EXIF 样片。

回归要求：

- 每次修改渲染、导出、元数据相关代码，都要跑样片回归。
- 如果导出报告变化，必须在变更说明中解释。

### 3.17 AI 增强能力

AI 功能放入 V2 付费规划，不进入免费 MVP。AI 的定位是“生成建议和自动化配置”，不是替代确定性渲染引擎。最终导出仍由 Java Engine 根据结构化参数执行，保证结果可控、可复现、可测试。

V2 付费 AI 能力：

- 智能模板推荐：根据照片横竖构图、明暗、色调、主体位置推荐白边、黑边、毛玻璃、拍立得、全画幅叠字等模板。
- 智能配色：从照片提取主色和辅助色，推荐边框色、渐变色、文字色和 Logo 深浅版本。
- 智能排版建议：识别主体安全区，避免文字压住人脸、建筑主体、天空亮部或画面视觉中心。
- 摄影信息文案生成：根据 EXIF 和用户设备库生成简洁参数文案或更有氛围感的标题、日期、签名。
- 批量智能套版：批量导入后自动按横图/竖图、明亮/暗调、人像/风景分组，并套用不同模板。
- 导出前智能检查：提示文字太小、对比度不足、边框过厚、裁剪可能切主体、Logo 和背景撞色等问题。
- EXIF 缺失补全助手：根据用户常用设备、文件名和手动输入生成候选参数，需用户确认后才写入文字或模板。

AI 使用边界：

- 默认关闭，用户主动启用。
- 免费 MVP 不依赖 AI，离线基础功能必须完整可用。
- AI 不直接输出最终图片，不直接修改原图。
- AI 只生成可编辑的模板参数、文字建议、颜色建议和风险提示。
- 如果需要云端模型，只上传低分辨率预览图和必要 EXIF，上传前必须明确提示。
- 后续可探索本地轻量模型，但不作为 V2 首要前提。

## 5. 技术架构

### 5.1 总体架构

- Electron 主进程负责应用生命周期、文件选择、保存目录选择、模板本地存储、未来打包和自动更新。
- React 渲染进程负责界面交互、状态编排、Canvas 即时预览。
- Java Engine 负责高质量图片读取、合成、导出、EXIF/ICC/TIFF/16-bit 等专业图像能力。
- 前端通过 localhost HTTP 调用 Java Engine。

### 5.2 为什么不采用 DOM 截图作为核心导出

DOM/CSS 模板适合快速做复杂视觉样式，但它的输出本质更接近屏幕截图，不适合作为本项目的专业高保真导出核心。最终导出仍应走 Java 图像引擎。

可以吸收 DOM 模板思想，但落地方式应是：

- 前端用模板预览和编辑。
- 后端用结构化 recipe 渲染。
- 模板最终必须能转换为可验证的 RenderRecipe。

### 5.3 模块规划

Electron：

- `main`：主窗口和生命周期。
- `preload`：安全 API 暴露。
- `ipc`：文件选择、目录选择、模板存储、未来系统字体读取。
- `engine`：Java 引擎健康检查、托管启动、日志。
- `packaging`：打包、更新、运行时集成。

Frontend：

- `app`：应用入口。
- `pages`：工作台页面。
- `features/queue`：图片队列。
- `features/preview`：预览和导出。
- `features/settings`：渲染设置。
- `features/template`：模板系统。
- `features/metadata`：EXIF、摄影信息合并、摄影资产库、摄影预设、变量插入。
- `features/presets`：视觉模板、输出预设。
- `services/engine`：引擎 API。

Java Engine：

- `controller`：HTTP API。
- `dto`：请求和响应。
- `model`：渲染模型。
- `service`：业务接口。
- `service/impl`：业务实现。
- `repository`：内存任务和预览存储。
- `util`：图像、颜色、文字、路径、元数据工具。
- `exception`：受控异常和统一错误响应。
- `config`：配置。

## 8. 阶段计划

### 阶段 1：可安装的摄影师 MVP

目标：让用户在 Windows 和 macOS 上无需登录、无需安装 Java，即可完成“导入 → 识别/补充摄影信息 → 套模板 → 预览 → 批量导出”。

任务：

- 固化数码与胶片拍摄画幅模型：M43、APS-C、135 全画幅、4433 中画幅，以及半格、135、645、6x6、6x7、6x8、6x9、6x10、6x12；6x12 保留，不以 6x10 替换。
- 完善数码 EXIF 读取、字段标准化和缺失值处理。
- 实现相机、镜头、胶片三类本地资产库。
- 实现可分类的摄影预设：创建、编辑、复制、删除、应用到单张/选中/全部图片。
- 实现字段优先级：每图覆盖 > 摄影预设 > EXIF > 空。
- 收敛视觉模板与摄影预设的边界，模板只负责排版，预设只负责拍摄身份。
- 完善拖拽导入、队列删除、单图预览、单图导出和批量导出。
- 保证 Canvas 预览、引擎预览、单图导出、批量导出共用同一套 RenderRecipe。
- 记录导出失败原因，支持失败项重试和导出后打开目录。
- 完成 Electron 托管 Java Engine、运行时路径、日志和异常恢复。
- 使用 electron-builder 产出 Windows `.exe` 和 macOS `.dmg`，内置 Java Runtime 和 Java Engine。

验收：

- 新用户在干净的 Windows/macOS 环境安装后可以直接启动，不要求登录、不要求安装 Java。
- 数码图片导入后可直接看到 EXIF 信息；胶片图片可通过分类摄影预设补齐信息。
- 画幅预设覆盖产品清单，且不会默认裁剪或改变原图尺寸。
- 预览与导出在文字、边框、渐变、摄影信息上保持一致。
- 单图和批量导出均能明确展示成功/失败状态，原图不会被覆盖。

### 阶段 2：效率与排版增强

目标：减少重复操作，让摄影师能更快地完成一组照片的统一出图和个别修正。

任务：

- 多段文字、左中右三栏布局、行距字距、文字阴影/描边/背景条。
- 预览缩放、拖拽、适应屏幕和网格辅助。
- EXIF/摄影信息变量插入器增强。
- Logo 自动识别和 Logo 图层。

## 10. 设计原则

- 默认不破坏原图色彩。
- 默认导出原图尺寸。
- 所有会影响画质、尺寸、色彩、元数据的选项都必须明确展示。
- 预览快，导出准。
- 模板可以漂亮，但底层数据必须结构化。
- 专业能力分阶段做，不在 MVP 阶段假装完整支持。
- 数码优先读取 EXIF，胶片通过可分类摄影预设补充，不强迫两者使用同一套录入流程。
- 摄影预设、视觉模板和图片队列职责分离；删除一个对象不能产生隐式级联删除。
- 本地优先且无需登录，应用离线时核心导入、排版和导出仍可用。
- 所有用户可见文案使用简体中文。
- 项目结构保持清晰，按功能域组织，避免文件随意堆叠。

## 11. 验收标准

### MVP 验收

- 可导入单张和多张图片。
- 可设置边框、渐变、文字和拍摄画幅。
- 可保存、加载、导入、导出模板。
- 可批量导出 JPEG/PNG。
- 数码照片可使用 EXIF 自动填充文字和摄影信息。
- 胶片照片可通过可分类摄影预设补充相机、镜头、胶片和画幅。
- 支持相机、镜头、胶片三类资产库。
- 字段优先级为每图覆盖 > 摄影预设 > EXIF > 空。
- 覆盖半格、135、645、6x6、6x7、6x8、6x9、6x10、6x12 以及 M43、APS-C、135 全画幅、4433 中画幅。
- Windows `.exe` 和 macOS `.dmg` 安装包可在无 Java 环境下启动。
- 不要求登录，图片和本地资产不离开用户电脑。
- 预览与导出整体一致。
- Electron 模式可日常使用，导出失败有明确反馈且不会覆盖原图。

### V2 验收

- 至少 8 套内置模板。
- 支持 Logo 自动识别。
- 支持多段文字和变量插入。
- 支持模板卡片、预览缩放和裁剪拖动。
- 支持更丰富的批量作用域和社交平台输出尺寸。

### 专业模式验收

- 支持 ICC Profile 保留。
- 支持 TIFF 高位深导出。
- 支持 EXIF/XMP/IPTC/GPS 尽量完整继承。
- 有样片测试和元数据对比结果。
